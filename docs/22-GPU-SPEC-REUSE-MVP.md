# GPU 入池规格复用 MVP

## 目标

同一资源池中的多张 GPU，如果硬件和算力参数完全相同，应关联同一条算力规格。
算力规格描述的是一类可分配资源，不是一张具体 GPU。

## 入池规则

GPU 入池时，后端使用以下字段匹配已有规格：

- 资源池
- GPU 品牌、型号、显存
- 独享或共享类型
- GPU 数量
- 共享比例
- CPU Core
- 内存 GiB

名称、展示名称和描述只用于展示，不参与资源规格匹配。

找到完全相同的规格时，新 GPU 直接关联已有规格；找不到时才使用前端提交的信息创建规格。

## 示例

两张 NVIDIA A100 80GB 均以 `1 GPU、8 Core、32 GiB` 加入独享池：

- GPU 数量：2
- 算力规格：1
- 规格容量：2 个独享规格节点

如果第二张卡使用不同的 CPU、内存或共享比例，则创建另一条规格。

## 共享池展示

共享池按 vGPU 算力规格聚合展示，不把物理卡的 `gpu_index` 显示为 vGPU 编号。
列表展示 Kubernetes Node、品牌、GPU 型号、vGPU 规格、切分比例、总规格节点数、
可用规格节点数、状态和使用状态。

总规格节点数使用 `关联 GPU 数量 × 单卡切分数` 计算。
可用规格节点数使用 `规格总容量 - 已分配租户配额` 计算。

底层继续保留物理卡编号，用于 Kubernetes 和 HAMi 识别规格来源，但不在共享池页面展示。

## 现有重复数据处理

仅合并没有业务冲突的重复规格：

1. 保留一条规格。
2. 将 GPU 的 `compute_spec_id` 改为保留规格。
3. 只有重复规格未被租户配额或推理部署引用时，才删除该规格。
