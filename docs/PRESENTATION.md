# 异构算力管理平台 ACMP-Compute

## 系统设计

---

### 模块一：资源池管理

**解决的问题**：如何将物理集群资源面向用户开放，提供配额管理和调度能力。

**设计思路**：平台将物理集群资源抽象为两层。

**逻辑资源池**：面向用户的配额单位，定义池的基本信息、支持的规格类型、配额上限。一个逻辑池对应一个配额单元。

**物理集群**：实际的 K8s 集群，包含节点标签（标识节点支持的 GPU 类型）、污点、资源上限（最大 CPU 核数、最大内存）。

两者通过关联表多对多绑定。同构模式下，一个逻辑池只绑定一个物理集群；异构模式下，一个逻辑池可绑定多个不同类型的物理集群。

**核心价值**：用户不感知底层集群细节，只关心资源池的规格和配额。

---

### 模块二：部署服务

**解决的问题**：用户提交一个部署请求（要几张什么类型的卡），平台如何自动转换成 K8s 可执行的资源申请。

**设计思路**：引入 ComputeSpec 作为中间抽象层。

ComputeSpec 是平台预设的"资源规格模板"，记录了每副本的 GPU 卡数、GPU 显存、GPU 算力、CPU 核数、内存大小，以及 Pod 的调度规则（nodeSelector、tolerations）。

用户只需指定 GPU 类型和数量，平台自动查询切分规格表，得到显存和算力值，生成规格名称（`auto-{GPU类型}-{GPU数量}g-{CPU}c-{内存}g`），查表判断是否已有同名规格：有则复用，无则新建。

**核心价值**：用户输入极简化，平台屏蔽 vGPU 切分细节。

---

### 模块三：调度器模式

**解决的问题**：同构池和异构池的部署路由逻辑完全不同，如何统一处理。

**设计思路**：抽象出调度器接口，按资源池模式分发。

**同构调度器**：部署时直接定位到唯一关联的物理集群，返回给调用方。

**异构调度器**：部署时根据请求的 GPU 类型，在多个关联物理集群中自动路由到节点标签匹配的那个集群。

两种调度器对外接口统一（pickCluster + validateDeployment），平台根据资源池的模式自动选用合适的调度器。

**核心价值**：同构场景简单直接，异构场景自动路由，调用方无需关心差异。

---

### 模块四：部署预校验

**解决的问题**：如何尽早发现部署请求中的错误，避免无效的配额扣减和 K8s 操作。

**设计思路**：部署前设置三重关卡，全部通过才进入配额扣减环节。

**第一重：GPU 类型校验**。检查请求的 GPU 类型是否在资源池支持范围内。同构池直接比对标签，异构池遍历集群查找匹配项。

**第二重：单副本资源上限校验**。检查用户申请的 CPU 核数和内存大小是否超出节点的资源上限。平台在节点纳管时记录每个节点的最大 CPU 和最大内存。

**第三重：配额校验**。在配额服务中检查 L1 池级配额和 L2 工作空间配额是否足够。

三重校验全部在配额扣减之前完成，任何一重不通过则直接拒绝请求。

**核心价值**：错误前置，用户体验好，后端开销小。

---

### 模块五：配额管理（双层）

**解决的问题**：如何实现精细化的资源配额控制，支持池级和工作空间级两个维度的配额管理。

**设计思路**：配额分为两层，分别对应不同的管理粒度。

**L1 池级配额**：限制整个资源池最多能分配多少副本数，所有工作空间共享。

**L2 工作空间级配额**：限制单个工作空间在特定资源池中最多能分配多少副本数。

部署时先扣 L1 配额，再扣 L2 配额。两层配额都充裕时才允许部署。删除部署时逐层释放配额。

**核心价值**：配额可精细到工作空间级别，支持多租户隔离。

---

### 模块六：K8s 资源构建与提交

**解决的问题**：如何将平台层的资源申请转换成真实的 K8s Deployment 和 Service。

**设计思路**：K8s 资源构建器根据 ComputeSpec 生成标准化的 YAML。

生成的 Deployment 包含：每副本资源限制（nvidia.com/gpu、nvidia.com/gpumem、nvidia.com/gpucores、cpu、memory、platform.io/{spec}）、nodeSelector（调度到对应 GPU 类型的节点）、tolerations（容忍节点污点）。

Service 根据镜像和端口配置生成。

构建完成后，提交到调度器选定的物理集群的对应 Namespace 中。

**核心价值**：平台屏蔽 K8s 细节，用户只需关心业务层面的部署需求。

---

### 模块七：节点管理

**解决的问题**：平台如何感知物理集群中节点的真实资源能力。

**设计思路**：提供节点扫描接口，定期或按需获取集群节点的资源信息。

扫描内容包括：节点名称、状态、GPU 类型、GPU 卡数、每卡显存、每卡算力、CPU 核数、内存大小、节点支持的切分规格列表。

扫描结果用于自动填充物理集群的资源上限（maxCpuCores、maxMemoryGib），以及前端展示节点详情供用户选择。

**核心价值**：平台资源信息与真实节点状态保持同步。

## 整体架构

```
┌─────────────────────────────────────────────────────────────┐
│                        用户请求                             │
└─────────────────────────────────────────────────────────────┘
                            ↓
┌─────────────────────────────────────────────────────────────┐
│                      资源池管理层                             │
│              同构模式 / 异构模式抽象                          │
└─────────────────────────────────────────────────────────────┘
                            ↓
┌─────────────────────────────────────────────────────────────┐
│                      部署服务层                              │
│         ComputeSpec 自动生成 / 复用                          │
└─────────────────────────────────────────────────────────────┘
                            ↓
┌──────────────────────┬──────────────────────────────────┐
│    预校验层           │           配额管理层               │
│  GPU 类型校验         │    L1 池级配额 + L2 工作空间配额    │
│  资源上限校验         │                                  │
└──────────────────────┴──────────────────────────────────┘
                            ↓
┌─────────────────────────────────────────────────────────────┐
│                      调度器层                                │
│              同构调度器 / 异构调度器                          │
└─────────────────────────────────────────────────────────────┘
                            ↓
┌─────────────────────────────────────────────────────────────┐
│                   K8s 资源构建与提交层                        │
│              Deployment + Service + Namespace              │
└─────────────────────────────────────────────────────────────┘
                            ↓
┌─────────────────────────────────────────────────────────────┐
│                      节点管理层                               │
│                   节点扫描与状态同步                          │
└─────────────────────────────────────────────────────────────┘
```
