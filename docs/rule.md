设计原则：
1. 设计方案时，只考虑基本原型的方案，以完成核心演示功能作为第一目标
2. 禁止过度设计，包括：高并发设计、事务性设计等，演示平台只有内网的两台机器组成的k9s集群
3. 接口字段与数据库库表字段，只填充最少，最必要的字段，禁止炫技增加字段
4. 每次都小型迭代改造，一定要先跟我讨论好方案之后，由我确认，将方案编写为文档之后，再进行执行

代码开发：
1. 优先编写阅读性好的代码，禁止简略代码逻辑
2. 关键代码位置一定要有注释！接口api的位置一定要有字段含义的解释
3. 代码实现逻辑仅保留正常核心流程的关键逻辑，并且在容易出错误位置，增加上帮助排查问题的注释
4. 新增代码前要判断是否是必须增加的，如果跟核心功能无关，不允许增加额外代码，必须改造代码，执行前必须告诉我
5. 每次功能改造，必须更新changelog
6. 代码实现的方式，一定要用简单方便阅读和维护的方式，禁止炫技，禁止使用过时的api或者操作方式
